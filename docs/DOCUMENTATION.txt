1. PROJECT SUMMARY
==============================================================================

Cake Delight is an online cake shop built with a microservices architecture.
Customers browse cakes, fill a basket, check out, receive an order
confirmation email and rate the cakes they bought. A demo Admin Dashboard
lets the shop add cakes, delete cakes and switch cakes available/unavailable.

The backend is five independent Spring Boot applications (an API Gateway and
four services). The frontend is a React single-page application served by
Nginx. All parts run in Docker containers, are started locally with Docker
Compose and are deployed on Kubernetes (Docker Desktop).


==============================================================================
2. OBJECTIVES
==============================================================================

  - Split a business application into small, independently deployable services.
  - Give each service its own database (database per service).
  - Provide one entry point for clients (API Gateway).
  - Use synchronous REST calls where an answer is needed immediately.
  - Use asynchronous messaging (RabbitMQ) where work can happen in the
    background (order confirmation email).
  - Package every component as a container image.
  - Deploy the whole system on Kubernetes with ConfigMap and Secret based
    configuration.

4.4 DESIGN PRINCIPLES

  - Single entry point: the browser calls only the API Gateway.
  - Database per service: no service reads another service's tables.
  - Layered services: controller -> service -> repository -> entity,
    with DTOs and mappers between layers.
  - Externalised configuration: hosts and credentials are environment
    variables, never hard-coded.
  - Loose coupling for side effects: checkout publishes an event; email
    sending happens afterwards in another service.

5. COMPONENTS AND RESPONSIBILITIES
==============================================================================

5.1 API GATEWAY (port 8080)
    - Routes /api/cakes/** to catalog, /api/orders/** and /api/baskets/** to
      order, /api/ratings/** to rating.
    - CORS for http://localhost:3000, :5173, :4173.
    - Logs every incoming request.
    - Actuator: health, info, gateway.

5.2 CATALOG SERVICE (port 8081, DB cake_catalog_db)
    - List cakes (filters: name, category, minPrice, maxPrice); public list
      shows only available cakes.
    - Admin list (all cakes), get by id, add, delete, toggle availability.
    - schema.sql creates the table, data.sql inserts 5 sample cakes.

5.3 ORDER SERVICE (port 8082, DB cake_order_db)
    - Basket: create, add item, update quantity, remove item, get.
    - Reads cake name, price and availability from the catalog service.
    - Checkout: creates the order (PLACED), marks the basket CHECKED_OUT and
      publishes the order.completed event.
    - Orders: list all, get by id, list by customer email.
    - Purchase verification endpoint used by the rating service.

5.4 RATING SERVICE (port 8084, DB cake_rating_db)
    - Submit rating (1-5) with optional review.
    - Confirms with the order service that the customer bought the cake.
    - One rating per cake per order.
    - Reviews of a cake, summary of a cake, all summaries, ratings by email.

5.5 NOTIFICATION SERVICE (port 8083, DB cake_notification_db)
    - No REST API. Consumes order.completed events from notification-queue.
    - Saves a notification (PENDING), sends an HTML confirmation email, sets
      the status to SENT or FAILED.

5.6 FRONTEND (Nginx port 80)
    - Pages: Home, Cakes, Basket, Orders, Admin Dashboard.
    - Calls the gateway at http://localhost:8080/api.
    - Remembers the basket id in the browser (localStorage).

5.7 INFRASTRUCTURE
    - MySQL 8.0: four databases created by an init script.
    - RabbitMQ 4 (management image): exchange "cake-delight" (topic, durable),
      queue "notification-queue" (durable), routing key "order.completed".

   The Admin Dashboard lists all cakes (including unavailable ones), adds a
   cake, deletes a cake and toggles availability. An unavailable cake is not
   shown in the shop and cannot be added to a basket.

8. DATA DESIGN
==============================================================================

DATABASE cake_catalog_db
  cakes(id PK, name, description, category, price, available, image_reference)

DATABASE cake_order_db
  baskets(basket_id PK, status, created_at, updated_at)
  basket_items(id PK, basket_id FK, cake_id, cake_name, unit_price, quantity)
      unique (basket_id, cake_id)
  orders(id PK, basket_id FK unique, customer_name, customer_email,
         delivery_address, total_amount, status, created_at)
  order_items(id PK, order_id FK, cake_id, cake_name, unit_price, quantity,
              subtotal)

DATABASE cake_rating_db
  ratings(id PK, order_id, cake_id, customer_name, customer_email, rating,
          review, created_at)
      unique (order_id, cake_id)

DATABASE cake_notification_db
  notifications(id PK, order_id, customer_name, customer_email, subject,
                message, status, created_at)

Basket items and order items keep a copy of the cake name and unit price at the
time of purchase, so later catalog changes do not change past orders.

9. API OVERVIEW  (all through the gateway, http://localhost:8080)
==============================================================================

  CATALOG
    GET    /api/cakes                          list available cakes (filters)
    GET    /api/cakes/admin                    list all cakes
    GET    /api/cakes/{id}                     get one cake
    POST   /api/cakes                          add a cake              -> 201
    PATCH  /api/cakes/{id}/availability        toggle availability     -> 204
    DELETE /api/cakes/{id}                     delete a cake           -> 204

  BASKET
    POST   /api/baskets                        create basket           -> 201
    POST   /api/baskets/{basketId}/items       add cake                -> 200
    GET    /api/baskets/{basketId}             get basket              -> 200
    PUT    /api/baskets/{basketId}/items/{itemId}   change quantity    -> 200
    DELETE /api/baskets/{basketId}/items/{itemId}   remove item        -> 204

  ORDER
    POST   /api/orders/checkout/{basketId}     checkout                -> 201
    GET    /api/orders                         all orders
    GET    /api/orders/{orderId}               one order
    GET    /api/orders/customer?email=         orders of a customer
    GET    /api/orders/{orderId}/verify-purchase?email=&cakeId=   true/false

  RATING
    POST   /api/ratings                        submit rating           -> 201
    GET    /api/ratings/cake/{cakeId}          reviews of a cake
    GET    /api/ratings/cake/{cakeId}/summary  average and count
    GET    /api/ratings/summary                summaries of all rated cakes
    GET    /api/ratings/customer?email=        ratings by a customer

  GATEWAY
    GET    /actuator/health
    GET    /actuator/gateway/routes

Full request and response bodies are in each service README.

11. CONTAINERISATION (DOCKER)
==============================================================================

  Backend services (5): multi-stage Dockerfile
     Stage 1: maven:3.9.9-eclipse-temurin-21  -> mvn clean package -DskipTests
     Stage 2: eclipse-temurin:21-jre          -> java -jar app.jar

  Frontend: multi-stage Dockerfile
     Stage 1: node:22-alpine   -> npm install, npm run build
     Stage 2: nginx:alpine     -> serves the built files on port 80

  Images built by Docker Compose:
     cake-delight-catalog-service     cake-delight-order-service
     cake-delight-notification-service cake-delight-rating-service
     cake-delight-api-gateway         cake-delight-frontend

  Official images: mysql:8.0, rabbitmq:4-management

  docker-compose.yml defines: 8 containers, a bridge network
  (cake-delight-network) and a named volume (mysql_data).

12. ORCHESTRATION (KUBERNETES)
==============================================================================

  Namespace ........ cake-delight
  Manifests ........ namespace, config, secret, mysql, rabbitmq,
                     catalog-service, order-service, rating-service,
                     notification-service, api-gateway, frontend
  Workloads ........ one Deployment (1 replica) per component
  Services ......... all ClusterIP (no NodePort)
  Config ........... ConfigMap injected with envFrom
  Secrets .......... Secret keys injected as individual environment variables
  Storage .......... PersistentVolumeClaim mysql-pvc (1Gi) mounted in MySQL
  Database init .... ConfigMap mysql-init mounted in /docker-entrypoint-initdb.d
  Images ........... cake-delight-*:latest, imagePullPolicy IfNotPresent
                     (uses the images built locally with Docker Compose)
  Access ........... kubectl port-forward of api-gateway (8080) and
                     frontend (3000 -> 80)

13. HOW TO RUN - DOCKER COMPOSE
==============================================================================

  cd docker
  cp .env.example .env            (Windows: copy .env.example .env)
  (edit .env: passwords and Gmail app password)
  docker compose build
  docker compose up -d
  docker compose ps
  docker compose logs -f api-gateway

  Open : http://localhost:3000          (application)
         http://localhost:8080/api/cakes (API)
         http://localhost:15672          (RabbitMQ management)

  Stop : docker compose down            (add -v to delete database data)


==============================================================================
14. HOW TO RUN - KUBERNETES
==============================================================================

  Run docker compose down first (ports 8080 and 3000 must be free).
  From the project root:

  kubectl config get-contexts
  kubectl config use-context docker-desktop
  kubectl get nodes

  kubectl apply -f k8s/namespace.yaml
  kubectl config set-context --current --namespace=cake-delight
  kubectl apply -f k8s/config.yaml
  kubectl apply -f k8s/secret.yaml
  kubectl apply -f k8s/mysql.yaml
  kubectl apply -f k8s/rabbitmq.yaml
  kubectl apply -f k8s/catalog-service.yaml
  kubectl apply -f k8s/order-service.yaml
  kubectl apply -f k8s/rating-service.yaml
  kubectl apply -f k8s/notification-service.yaml
  kubectl apply -f k8s/api-gateway.yaml
  kubectl apply -f k8s/frontend.yaml

  kubectl get pods -n cake-delight
  kubectl get svc -n cake-delight
  kubectl get secrets -n cake-delight

  Terminal 1: kubectl port-forward -n cake-delight svc/api-gateway 8080:8080
  Terminal 2: kubectl port-forward -n cake-delight svc/frontend 3000:80

  Open http://localhost:3000

  Clean up: kubectl delete namespace cake-delight
